## About

aview draws a picture as ASCII art in the terminal through [aalib](#port-aalib), with keys for
zoom, contrast, brightness and gamma; `aaflip` beside it plays FLI and FLC animations the same
way. aview reads only PNM images, and `asciiview`, the shell front end installed with the two
programs, converts any other format to a grey PGM before handing it over.

## Flags

- `-Wno-implicit-function-declaration`, `-Wno-implicit-int`, `-Wno-int-conversion`,
  `-Wno-incompatible-pointer-types`, `-Wno-return-mismatch`,
  `-Wno-declaration-missing-parameter-type` — Turn back into warnings the old-style C that GCC 14
  and later reject. The `configure` script is generated by autoconf 2.13, and its compiler test,
  `main(){return(0);}`, is such C: without these switches configure decides the compiler cannot
  create executables (see
  [`C compiler cannot create executables`](../../../../docs/kdos/05-developer/build-troubleshooting.md#c-compiler-cannot-create-executables)).
  The exported `CFLAGS` reach the compile of aview's own sources as well.

## Patches

- `imagemagick7.patch` — Makes `asciiview` try `magick <file> -colorspace gray pgm:-` first, before upstream's `anytopnm` and `convert`. [imagemagick](#port-imagemagick) 7 installs the `convert` name only when configured with `--enable-legacy-support`, which the tree's recipe does not pass, so `magick` is the converter the script can reach with only `depends` installed.

## Notes

`asciiview` converts with whatever is on `PATH`. `anytopnm` comes from [netpbm](#port-netpbm),
which is a port but not in `depends`; with it installed, `magick` is still tried first.
