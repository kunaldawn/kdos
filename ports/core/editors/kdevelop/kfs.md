## About

KDevelop is KDE's IDE, strongest on C and C++: its code model is libclang, from the
[clang](#port-clang) port, and it understands CMake, meson, qmake and plain make projects. The
port builds it with the plugins that drive clang-tidy, [cppcheck](#port-cppcheck), the
[gdb](#port-gdb) and [lldb](#port-lldb) debuggers, git, patch review, and the Qt Help and manual
page documentation, which it shows in a QtWebEngine view.

## Flags

- `-D CMAKE_C_STANDARD=23` — Together with `-D CMAKE_C_EXTENSIONS=ON`, compile C as GNU C23. KDE's
  compiler settings make C strict C99 unless a standard is given, and the CMake plugin's lexer,
  `plugins/cmake/parser/cmListFileLexer.c`, includes `QtGlobal` through `cmStandardLexer.h` and
  calls `fileno` and `strdup`.
  Qt's headers use `static_assert`, a keyword only from C23, and a strict ISO mode hides `fileno`
  and `strdup`; GNU C23 has all three.
- `-D BUILD_BENCHMARKS=OFF` — No benchmark programs. Upstream builds them whenever optimisation is
  on.
- `-D BUILD_DOC=ON` — Build the handbook with [kdoctools](#port-kdoctools). It is upstream's
  default.
- `-D BUILD_executeplasmoid=OFF` — Leave out the launcher that runs a Plasma widget under
  development through Plasma's `plasmoidviewer`. Like every plugin added with `ecm_optional_add_subdirectory`,
  it is built unless its `BUILD_<name>` switch is off.
- `-D BUILD_ghprovider=OFF` — Leave out the GitHub project provider, a front end to an online
  service.
- `-D CMAKE_REQUIRE_FIND_PACKAGE_Clang=ON` — This switch and the other `CMAKE_REQUIRE_FIND_PACKAGE_`
  switches (`KompareDiff2`, `Qt6Help`, `Qt6WebEngineWidgets`, `KF6Purpose`, `Boost`, `KSysGuard`,
  `KDevelopPGQt`) make each of those `find_package` calls fail configure when its package is
  missing. Five are optional upstream, and a miss builds on without the part that uses it: patch
  review ([libkomparediff2](#port-libkomparediff2)) and patch sharing ([purpose](#port-purpose)),
  the Qt Help documentation, the debuggers' "attach to process" list
  ([libksysguard](#port-libksysguard)), and the QMake builder and manager, whose parser is
  generated by [kdevelop-pg-qt](#port-kdevelop-pg-qt). Clang, Boost and `Qt6WebEngineWidgets` are
  marked required only through `set_package_properties`, so a miss of one of them stops
  configure at the closing feature summary; the switch stops it at the `find_package` call.
- `-D CMAKE_DISABLE_FIND_PACKAGE_SubversionLibrary=ON` — This switch and the other
  `CMAKE_DISABLE_FIND_PACKAGE_` switches (`OktetaKastenControllers`, `KastenControllers`,
  `OktetaGui`, `heaptrack`, `heaptrack_gui`, `ClazyStandalone`) keep configure from looking for
  Subversion's libraries, Okteta's libraries and the `heaptrack`, `heaptrack_gui` and
  `clazy-standalone` programs, none of which is a port. Without Subversion's libraries the
  Subversion plugin is not built. Upstream's own CMake files already disable the three Okteta
  packages, so the Okteta plugin and the debugger's memory viewer are never built. The heaptrack
  and Clazy plugins are built either way: those `find_package` calls only look for the program,
  which the plugin runs when the user starts an analysis.

## Notes

Translations are not built (`KF_SKIP_PO_PROCESSING`), and the package prune removes the
translated handbooks `kdoctools` produces; see
[Size and language policy](../../../../docs/kdos/05-developer/writing-ports.md#size-and-language-policy).

The two visible menu entries are replaced. `KAboutData` sets the desktop file name, and so the
Wayland app_id, to `org.kde.kdevelop`, which both entries give as `StartupWMClass`. The
*KDevelop (Pick Session)* entry is hidden with `NoDisplay=true`; the main entry's *Open a Session*
action runs the same `kdevelop --ps`. `org.kde.kdevelop_kdev4.desktop`, the hidden handler for
`.kdev4` project files, is left as upstream installs it.
