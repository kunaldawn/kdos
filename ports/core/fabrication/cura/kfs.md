## About

UltiMaker Cura is a slicer that prepares 3D models for FDM printing, with UltiMaker's printer
definitions and material profiles. It is a Python program on Qt 6 through
[python3-pyqt6](#port-python3-pyqt6), built on the [uranium](#port-uranium) application framework,
and it slices with the separate [curaengine](#port-curaengine) binary. Upstream ships it through
Conan and PyInstaller and gives it no install rules, so `build.sh` lays out the files itself.

## Flags

- `--no-deps` — With `--no-index`, `--find-links=vendor` and `--no-build-isolation`: pip installs
  exactly the three vendored modules it is named, from the unpacked bundle alone, with the build
  backends of the tree's own ports, and resolves nothing. See Notes.
- `--ignore-installed` — Installs the three modules into `$PKG` even when the build root already
  has a copy, so the package always carries them.

## Notes

The Python modules that only Cura imports are vendored: trimesh for the
AMF reader and the glTF and other mesh readers of `TrimeshReader`, and zeroconf with ifaddr for finding network printers. They are
named, at their versions, in `pypackages` in `kpkgbuild`, so `ports/fetch` downloads exactly those
source distributions (with the build requirements it follows from them) into
`cura-vendor-<version>.tar.xz`, which `kpkgbuild` pins by its `sha256` like any other source (see
[Vendoring](../../../../docs/kdos/05-developer/writing-ports.md#vendoring)).
Every other module Cura imports is a port in `depends`, the account token store [python3-keyring](#port-python3-keyring)
among them.

The layout is the one Cura and Uranium search from a launcher in `/usr/bin`: the `cura` package
and Charon in `site-packages`, plugins under `/usr/lib/cura/plugins`, resources under
`/usr/share/cura`, and CuraEngine at `/usr/bin/CuraEngine`. Charon, the UFP container library, is
the one module of libCharon that Cura imports; it comes from a second source pinned to the commit
`_charon`. The material profiles come from fdm_materials at the same release as Cura, a third
source.

`CuraVersion.py` is generated by Conan from upstream's `CuraVersion.py.jinja`; `build.sh` writes
the same file with the values a release build fills in. The cloud and marketplace addresses in it are
upstream's.

Five plugins are left out: `SentryLogger` (crash reports), `SliceInfoPlugin` (anonymous slice
statistics to `statistics.ultimaker.com`) and `FirmwareUpdateChecker`, which report to or poll
UltiMaker's servers; `3DConnexion`, which imports `pynavlib`, not a port; and `MakerbotWriter`,
which imports the `pyDulcificum` converter, not a port either.

`build.sh` leaves out `resources/i18n`, so the interface shows its English source strings. Test
directories and byte-code caches are removed, every file is made mode 644, and the modules are
byte-compiled against their installed paths. The three `test` lines at the end stop the build if
the base printer definition, the material profiles or the CuraEngine backend plugin are missing.

`/usr/bin/cura` is a small launcher that calls `QGuiApplication.setDesktopFileName("cura")` and
then runs `/usr/lib/cura/cura_app.py`. Without a desktop file name, Qt builds the Wayland app_id
from Uranium's organisation domain and the interpreter's name, which matches no desktop entry. The
launcher names the entry before Cura's code runs and leaves `argv[0]` as `/usr/bin/cura`, from
which Uranium derives its install prefix.

The desktop entry claims no MIME types: [prusaslicer](#port-prusaslicer)'s entry claims the model
types.
