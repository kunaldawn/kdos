## About

[mqttui]{.idx} subscribes to an MQTT broker and shows the topic tree in the terminal, with each
topic's payloads as they arrive. Its subcommands also publish, log topics to standard output, read
one value for a script (`read-one`) and clean retained topics. Where `mosquitto_sub` prints a stream of
messages, mqttui shows the topic tree they belong to.

## Notes

The crates come from the vendor bundle, `mqttui-vendor-<version>.tar.xz`, pinned with its own
`sha256 =` line and unpacked at the top of the tree; cargo builds `--frozen --offline` from it (see
[Vendoring](../../../../docs/kdos/05-developer/writing-ports.md#vendoring)).

Its TLS goes through rustls with the default AWS-LC provider, compiled into the binary by
`aws-lc-sys`. mqttui has no build feature that moves its TLS onto the system OpenSSL, so the
copy is listed in `/usr/share/kdos/bundled.txt`, which `kdos cve` reads; see
[Bundled copies](../../../../docs/kdos/03-architecture/packaging.md#bundled-copies).
A vendor bundle that moves `aws-lc-sys` changes mqttui's row there.

The manual pages, `mqttui.1` and one for each subcommand, are generated by the crate's `build.rs`
with `clap_mangen` into `target/manpages`, which `build.sh` installs from; the shell completions it
writes beside them into `target/completions` are not installed.
