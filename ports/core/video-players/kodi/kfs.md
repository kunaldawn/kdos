## About
[Kodi]{.idx} is a ten-foot media centre: a full-screen interface for local and network video,
music and pictures, driven by a remote, a keyboard or a game pad, and extended by add-ons written
in Python. This port builds it for the Wayland windowing system, drawing with OpenGL ES through
EGL and decoding through VA-API, with a menu entry that also offers to open it full screen.

## Flags
- `-DCORE_PLATFORM_NAME=wayland` — Build Kodi's Wayland windowing back end, the only one: no X11
  and no direct-to-DRM (GBM) build.
- `-DAPP_RENDER_SYSTEM=gles` — Render with OpenGL ES rather than desktop OpenGL.
- `-DENABLE_VAAPI=ON` — Hardware video decoding through [libva](#port-libva).
  `-DENABLE_VDPAU=OFF` builds no VDPAU path, an X11 interface with no port here.
- `-DENABLE_GOLD=OFF` — With `-DENABLE_LLD=OFF`, `-DENABLE_MOLD=OFF` and `-DUSE_LTO=OFF`: link
  with the ordinary `ld`, take no alternative linker, and do no link-time optimisation. The
  [binutils](#port-binutils) port builds no gold.
- `-DENABLE_SSE=ON` — With `-DENABLE_SSE2=ON` and `-DENABLE_SSE3=OFF` through
  `-DENABLE_AVX2=OFF`: fix the SIMD level at SSE2, the x86-64 baseline. Left alone, Kodi's
  `FindSSE.cmake` reads the builder's `/proc/cpuinfo`, and `ArchSetup.cmake` turns on every level
  up to SSE4.1 that the building processor has, for every machine the package later runs on.
- `-DENABLE_TESTING=OFF` — Build no test suite. `-DENABLE_EVENTCLIENTS=OFF` builds none of the
  event-client programs that send remote-control events to Kodi over the network.
- `-DENABLE_PYTHON=ON` — The optional features are each named `ON`. Left unset, a missing
  library drops its feature with only a line in the configure summary; set `ON`, a missing one
  stops the configure. The features are Python add-ons, UPnP, optical discs with libdvdcss, AirTunes
  ([shairplay](#port-shairplay)), ALSA, PulseAudio and PipeWire output, Avahi, BlueZ, Blu-ray,
  libcap, dav1d, D-Bus, LCMS2, the web server ([libmicrohttpd](#port-libmicrohttpd)), plist
  (AirPlay), Samba shares, udev, udfread, XSLT, HDMI-CEC ([libcec](#port-libcec)), NFS shares
  ([libnfs](#port-libnfs)), ISO9660++ (libcdio's C++ binding) and the LIRC client.
- `-DENABLE_MDNS=OFF` — With `-DENABLE_SNDIO=OFF`, `-DENABLE_MARIADBCLIENT=OFF` and
  `-DENABLE_MYSQLCLIENT=OFF`: build without the mDNSResponder client library (`dnssd` or
  `mDNSEmbedded`; Zeroconf goes through Avahi), sndio output, and a MariaDB or MySQL server as a
  shared media library.
- `-DENABLE_INTERNAL_FFMPEG=ON` — Build Kodi's pinned FFmpeg and link it in. Kodi's
  `FindFFMPEG.cmake` asks pkg-config for every FFmpeg library including libpostproc, and the
  [ffmpeg](#port-ffmpeg) port is a release that has no libpostproc.
- `-DENABLE_INTERNAL_CROSSGUID=ON` — With `-DENABLE_INTERNAL_FLATBUFFERS=ON`,
  `-DENABLE_INTERNAL_FMT=ON`, `-DENABLE_INTERNAL_SPDLOG=ON`, `-DENABLE_INTERNAL_FSTRCMP=ON`,
  `-DENABLE_INTERNAL_PCRE=ON` and `-DENABLE_INTERNAL_KISSFFT=ON`: build these from the copies Kodi
  pins and link them in statically. crossguid, flatbuffers, fstrcmp, PCRE 1 and kissfft are not
  ports. [fmt](#port-fmt) is, at a release Kodi does not build against, and Kodi's
  `CMakeLists.txt` forces an internal spdlog whenever fmt is internal.
- `-DENABLE_INTERNAL_DAV1D=OFF` — With `-DENABLE_INTERNAL_CEC=OFF`, `-DENABLE_INTERNAL_NFS=OFF`,
  `-DENABLE_INTERNAL_RapidJSON=OFF`, `-DENABLE_INTERNAL_TAGLIB=OFF`,
  `-DENABLE_INTERNAL_UDFREAD=OFF` and `-DENABLE_INTERNAL_GTEST=OFF`: take each of these from its
  port, never from Kodi's pinned copy. gtest is looked for only when `-DENABLE_TESTING` is on, so
  it is not in `depends`.
- `-DCROSSGUID_URL` — With `-DLIBDVDCSS_URL`, `-DLIBDVDNAV_URL`, `-DLIBDVDREAD_URL`,
  `-DFFMPEG_URL`, `-DFMT_URL`, `-DSPDLOG_URL`, `-DFLATBUFFERS_URL`, `-DFSTRCMP_URL` and
  `-DPCRE_URL`: give every library Kodi would download as a local archive, a source of this
  recipe. `_src` names the copy beside the recipe after `make fetch`, or the one in kpkg's source
  directory on a machine that rebuilds from its own cache. Kodi checks each archive against the
  hash in its own `tools/depends/target/*/*-VERSION` file before it builds it.
- `-Dgroovy_SOURCE_DIR` — With `-Dapache-commons-lang_SOURCE_DIR` and
  `-Dapache-commons-text_SOURCE_DIR`: where the Groovy and Apache Commons jars are unpacked. The
  Python add-on bindings are generated by a Groovy script run on [openjdk](#port-openjdk) at build
  time; given these directories, the build does not download them. Groovy must be a release that
  reads the class files of the openjdk port's Java; an older one stops with "Unsupported class
  file major version"
  ([A JVM tool older than the JDK](../../../../docs/kdos/05-developer/build-troubleshooting.md#a-jvm-tool-older-than-the-jdk)).
- `-Wl,-z,stack-size=2097152` — Ask for a 2 MiB default thread stack. musl gives a thread 128 KiB
  unless the executable asks for more, and Kodi's threads need more than that.
- `-D_LARGEFILE64_SOURCE` — Kodi hands its compiler flags, and nothing else, to each library it
  builds from source, and some of them (spdlog and Kodi's libdvdread among them) call `fseeko64`
  and `fstat64`, which musl declares only under this macro, so it goes into `CFLAGS` and
  `CXXFLAGS`.
- `CMAKE_POLICY_VERSION_MINIMUM=3.5` — Exported, rather than given as a `-D`, because PCRE's own
  CMake run asks for a CMake older than 3.5 and only the environment reaches that nested run
  ([An old CMake policy floor](../../../../docs/kdos/05-developer/build-troubleshooting.md#an-old-cmake-policy-floor)).

## Patches
- `fix-musl-incompability.patch` — In the DLL loader's C runtime emulation, treats every non-glibc C library like the BSDs: `fpos_t` is handled as a plain 64-bit offset instead of glibc's `__pos` field, `__off_t` and `off64_t` are defined where glibc would provide them, and `_PATH_MOUNTED` and `_PATH_MNTTAB` get fallback definitions.
- `gcc13.patch` — Adds `#include <cstdint>` to five headers that use the fixed-width integer types without it ([A standard header the source never includes](../../../../docs/kdos/05-developer/build-troubleshooting.md#a-standard-header-the-source-never-includes)).
- `lfs64.patch` — Replaces the glibc 64-bit file calls and types (`stat64`, `fstat64`, `statvfs64`, `fseeko64`, `lseek64`, `off64_t`) with the plain ones, which are 64-bit on musl.
- `fmt-imported-configs.patch` — `FindFmt.cmake` sets the imported target's configuration list twice, the second call replacing the first, so a Release build is told only of the Debug library, `libfmtd.a`, which the internal build never makes. The patch appends each configuration ([An imported library that names only its Debug build](../../../../docs/kdos/05-developer/build-troubleshooting.md#an-imported-library-that-names-only-its-debug-build)).
- `texturepacker-giflib6.patch` — TexturePacker, the build tool that packs the skins' images, tests for giflib 5 exactly and takes the giflib 4 calls for any other version; the patch tests for 5 or later, which the [giflib](#port-giflib) port's 6 is ([A version test that excludes a newer major release](../../../../docs/kdos/05-developer/build-troubleshooting.md#a-version-test-that-excludes-a-newer-major-release)).
- `pcre-cmp0026.patch` — Adds one more patch to the list `FindPCRE.cmake` applies to the internal PCRE, which drops its `cmake_policy(SET CMP0026 OLD)`, a setting CMake 4 refuses ([A policy set to its removed behaviour](../../../../docs/kdos/05-developer/build-troubleshooting.md#a-policy-set-to-its-removed-behaviour)).
- `platformdefs-limits.patch` — Includes `<limits.h>` in `PlatformDefs.h`, which defines `MAX_PATH` as `PATH_MAX` and relied on another header to declare it.

## Notes
- **Patch order.** One hunk of `lfs64.patch` in `emu_msvcrt.cpp` carries, as context, a line
  that `fix-musl-incompability.patch` writes, so it applies only after that patch, as the loop in
  `build.sh` orders them.
- **Parallel link.** The static `libcrossguid.a` is not a tracked output of its external project,
  so a parallel build can reach the link before it exists; `ninja crossguid` builds it first.
- **What `build.sh` removes.** The X and Wayland session files (no display manager reads them),
  the firewalld service definitions (no firewalld runs here), and `/usr/bin/TexturePacker`.
- **Add-on updates default to never.** Kodi otherwise contacts its add-on repository at every
  start. `build.sh` installs `system/settings/appliance.xml`, the settings file Kodi loads after
  every other so that it can override their defaults, setting `general.addonupdates` to 2,
  "Never check for updates" (`AUTO_UPDATES_NEVER` in `system/settings/settings.xml`). Settings > System > Add-ons turns updates back on.
- **The menu entry is replaced** so that `StartupWMClass` is `Kodi`, Kodi's application name and
  its Wayland app_id.
- The Groovy and Commons jars, the fonts bundled in the skins and the web interface's JavaScript
  are the exceptions to compiling everything here; see
  [What is built from source](../../../../docs/kdos/05-developer/writing-ports.md#what-is-built-from-source).
