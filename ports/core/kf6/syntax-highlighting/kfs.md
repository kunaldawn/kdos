## About

KSyntaxHighlighting is the syntax highlighting engine of [kate](#port-kate) and
[ktexteditor](#port-ktexteditor): more than 400 language definitions and the colour themes, all
compiled into the library as resources, a highlighter for any `QTextDocument`, and the
`ksyntaxhighlighter6` command that writes highlighted HTML or ANSI-coloured text from the shell.
[kio-extras](#port-kio-extras)'s text thumbnails, [kmail](#port-kmail)'s code blocks and
[labplot](#port-labplot) use it too.

## Flags

- `-D CMAKE_REQUIRE_FIND_PACKAGE_Python=ON` — Make a Python interpreter a requirement. The build
  generates the Jinja definitions with a Python script, and upstream looks for the interpreter as
  optional and builds without those definitions when it is missing. [python3](#port-python3) is in
  `depends` for it.
- `-D CMAKE_DISABLE_FIND_PACKAGE_XercesC=ON` — Never look for Xerces-C. When upstream finds it,
  `katehighlightingindexer`, the build-time tool that compiles the definitions into the library,
  also validates each definition file against the XML schema. The tool is not installed and the
  library is the same either way, while [xerces-c](#port-xerces-c), built in an earlier phase,
  would otherwise be found in every build root without being in `depends`.
- `-D KF_SKIP_PO_PROCESSING=ON` — Build none of the Qt translation catalogues under `poqm/`,
  which `ecm_install_po_files_as_qm()` would compile into `.qm` files. The strings in the source
  are English, and the package-wide English-only rule (see
  [Size and language policy](../../../../docs/kdos/05-developer/writing-ports.md#size-and-language-policy))
  would remove every catalogue in another language.

## Notes

[perl](#port-perl) is a requirement of the configure: the PHP definitions are generated by a Perl
script.
