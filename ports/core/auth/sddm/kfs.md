## About

SDDM is the login screen. Its daemon, `sddm`, runs as root on tty1, started from `/etc/inittab`
through `kdos-dm`; it owns the seat through [elogind](#port-elogind), and starts the greeter as
the `sddm` system account on its own compositor: `kwin_wayland` from [kwin](#port-kwin), named by `[Wayland] CompositorCommand` in
`/etc/sddm.conf.d/00-kdos.conf`. The greeter, `sddm-greeter-qt6`, is a QML program that draws the
theme `[Theme] Current=` names. After a password is accepted, `sddm-helper` opens the user's PAM
session, writes the login to utmp, and runs the session's `Exec=` line through the program in
`[Wayland] SessionCommand`. `DisplayServer=wayland` keeps any X server off the login path; the
greeter links libxcb only for its X11 keyboard backend, which a Wayland greeter never uses (see
[No Xorg server](../../../../docs/kdos/01-philosophy/principles.md#no-xorg-server-and-one-carve-out)).

The configuration under `/etc/sddm.conf.d/`, the `sddm` account and `kdos-dm` are the tree's
`fs/` overlay, not this package. The PAM stacks `/etc/pam.d/sddm`, `sddm-autologin` and
`sddm-greeter`, the greeter's real-time limit and the autologin's environment file are written by
`build.sh` (see Notes). The boot-to-greeter chain is in
[Boot and init](../../../../docs/kdos/03-architecture/boot-and-init.md).

## Flags

- `-D CMAKE_POLICY_VERSION_MINIMUM=3.5` — SDDM 0.21.0 declares `cmake_minimum_required(VERSION
  3.4)`, which the tree's CMake refuses. Alpine carries a patch raising the line to 3.5; the flag
  does the same without one.
- `-D CMAKE_INSTALL_LIBDIR=lib` — SDDM takes its paths from `GNUInstallDirs`, not from ECM, so
  this is the library-directory switch it reads.
- `-D BUILD_WITH_QT6=ON` — Build the Qt 6 daemon, greeter and QML components. The default is
  Qt 5, and the Plasma greeter theme is Qt 6 QML.
- `-D NO_SYSTEMD=ON` — Look for no systemd. Without it the configure probes `systemd.pc`, and the
  journald and unit-file paths with it.
- `-D USE_ELOGIND=ON` — Look for `libelogind` and compile `loginctl poweroff` and
  `loginctl reboot` in as the halt and reboot commands. SDDM reaches logind's seats and sessions
  over D-Bus whichever is set; this flag changes only those two commands and the PAM module named
  in upstream's greeter stack. The probe is a `pkg_check_modules` that is not required, so
  `build.sh` checks `ELOGIND_FOUND` in the CMake cache after the configure: a build that missed
  elogind would compile in `/sbin/shutdown` and still succeed.
- `-D ENABLE_JOURNALD=OFF` — Log to the file and syslog, never to journald.
- `-D INSTALL_PAM_CONFIGURATION=OFF` — Install none of upstream's PAM files. They include
  `system-local-login`, which KDOS does not have, name `pam_gnome_keyring`, and give the greeter
  a stack without `pam_turnstile`; `build.sh` writes KDOS's own after the install, and with this
  on upstream's would be installed over them.
- `-D BUILD_MAN_PAGES=ON` — `sddm(1)`, `sddm-greeter(1)`, `sddm.conf(5)` and
  `sddm-state.conf(5)`, generated by `rst2man` from [python3-docutils](#port-python3-docutils).
  The configure does not stop when `rst2man` is missing; the build does.
- `-D UID_MIN=1000` — With `-D UID_MAX=60000`: the range of accounts the greeter lists, the same
  as `/etc/login.defs`. Given on the command line, the configure does not read `login.defs` from
  the build root, which a chroot that lacks it would make fatal.
- `-D RUNTIME_DIR=/run/sddm` — Where the daemon keeps X authority files. Without systemd the
  default is `/var/run/sddm`.
- `-D DBUS_CONFIG_FILENAME=sddm_org.freedesktop.DisplayManager.conf` — The system-bus policy
  under `/usr/share/dbus-1/system.d`, named after the package that owns it, as Alpine names it.
- `-D CMAKE_CXX_STANDARD_LIBRARIES=-lutmps` — With `-I/usr/include/utmps` in `CXXFLAGS`: musl's
  `utmpx` functions do nothing, so `sddm-helper` writes its utmp and wtmp records through
  [utmps](#port-utmps), as [shadow](#port-shadow) does. The library goes at the end of every link
  line, and `--as-needed` keeps it only in `sddm-helper`, the one program that calls it.

## Notes

Alpine's 0.21.0-r10 carries three patches, and none is applied here.
`0001-pam-path-fix.patch` points upstream's PAM files at Alpine's `base-*` stacks; KDOS installs
none of upstream's PAM files (`INSTALL_PAM_CONFIGURATION=OFF`), so it has nothing to change.
`0002-disable-automatic-portal-launching.patch` sets `QT_NO_XDG_DESKTOP_PORTAL=1` in the
greeter's `main()`; 0.21.0's `sddm-helper` already sets that variable in the environment of every
greeter-class session (`src/helper/Backend.cpp`), so the patch repeats it.
`0003-CMake-Raise-required-version-to-3.5.patch` is the `CMAKE_POLICY_VERSION_MINIMUM=3.5` flag.

The greeter session gets `QT_WAYLAND_SHELL_INTEGRATION=xdg-shell` from the daemon, and
`GreeterEnvironment` in `00-kdos.conf` is applied after it, which is how
`QT_WAYLAND_SHELL_INTEGRATION=layer-shell` reaches the Plasma greeter theme.

`USE_ELOGIND` needs `NO_SYSTEMD` with it: the configure looks for `libelogind` only when both are
on. The package links no libelogind and no libsystemd.

The package installs `/usr/share/sddm/scripts/wayland-session`, upstream's session wrapper.
KDOS's `00-kdos.conf` names its own wrapper in `SessionCommand` instead, and the stock script stays
for a configuration that drops the key. The X11 scripts (`Xsession`, `Xsetup`, `Xstop`) and
`sddm-helper-start-x11user` are installed too and never run while `DisplayServer=wayland`.

Upstream's test programs under `test/` are built with no switch to skip them, and none is
installed. Translations are built and installed to
`/usr/share/sddm/translations-qt6`, and the package-wide English-only rule removes every
catalogue but the source language's (see
[Size and language policy](../../../../docs/kdos/05-developer/writing-ports.md#size-and-language-policy)).

The upstream session power menu falls back to UPower when logind does not answer on the system
bus. elogind always answers on KDOS, so UPower is not a dependency.

**The PAM stacks.** `sddm` and `sddm-autologin` include `system-login`, from [pam](#port-pam),
which is where every KDOS login is registered with [elogind](#port-elogind) and handed to
[turnstile](#port-turnstile), so a desktop login gets the same session, runtime directory, session
bus and real-time limits as a console one. `pam_kwallet5` comes after `system-login` in the
session phase because it puts the wallet's socket in the runtime directory turnstile has just
made; in the auth phase it comes after `pam_unix`, because it only keeps the password `pam_unix`
was given, and with no password in hand it would prompt for one itself. That is also why
`sddm-autologin` has no `pam_kwallet5` auth line: an autologin has no password, and the wallet
asks for its own the first time it is opened. Both `pam_kwallet5` lines start with `-`, so the
stacks work without kwallet-pam installed, and it is not in `depends`.

`sddm-autologin` refuses any account below uid 1000 (`pam_succeed_if`), so a `kde_settings.conf`
naming `root` or a system account starts nothing. The one exception is `plasma-setup`, the
system account the OEM first boot logs in to run the setup wizard: the first `pam_succeed_if`
line matches that name alone and, on a match, skips the uid check. Without it the wizard's
autologin is refused and an OEM install never leaves the login screen. `root` and `sddm` stay
refused.

`sddm-greeter` is the `sddm` account's session for the greeter. `pam_turnstile` is `required`
there, not optional: turnstile is the only creator of `/run/user/<sddm uid>`, and the greeter's
KWin refuses to start without `XDG_RUNTIME_DIR`, so a session without it is a black screen that
looks like a working one. That is why turnstile is in `depends`. turnstile's KDOS backend starts
no user services for a uid below 1000, so the greeter gets a runtime directory and no bus,
PipeWire or timers. `pam_limits` with `/etc/security/limits.d/30-sddm.conf` grants the account
real-time priority 1, which is what KWin's `SCHED_RR` request needs; the capability the kwin
binary carries upstream does not survive kpkg's tar. The limit is a hard one `pam_limits` can
raise only as root, which `sddm-helper` is.

**An autologin can start locked, and only an autologin.** `sddm-autologin` runs `pam_env` with
`/etc/security/sddm-autologin.conf`, which puts `/etc/kdos/autologin-xdg` first in
`XDG_CONFIG_DIRS`, ahead of `/etc/xdg` and the distribution's defaults in `/usr/share/kdos/xdg`.
The image ships no such directory, so on its own the line changes nothing. The installer creates
it on a single-account machine with an encrypted root, with a `kscreenlockerrc` of
`[Daemon] LockOnStart=true`: KWin's screen locker then locks before the desktop is shown, and the
lock screen is that machine's login. The installer's "no password after the disk passphrase"
answer leaves the directory out. The setting lives with the stack rather than in
`/etc/xdg/kscreenlockerrc` or a home directory because it belongs to the autologin, not to the
account: a password login through `sddm` never reads the directory, so turning autologin off in
System Settings → Login Screen does not leave every later login asking for the password a second
time, and a second account is never locked at its first login. `pam_env` is `optional`, and a
missing file is skipped: an autologin is never refused over it.

The greeter runs as `sddm`, uid and gid 64, home `/var/lib/sddm`, shell `/sbin/nologin`: an
account `fs/etc/passwd`, `group` and `shadow` carry rather than one a postinstall makes. Its id is
fixed and below 101 because `useradd -r`, which every service account's postinstall runs, hands
out ids from 999 downwards, so a fixed id in that range could be one a tree that already holds
those accounts has given to somebody else. `kdos-dm` makes `/var/lib/sddm` and hands it to the
account at every start, since nothing else creates a system account's home; SDDM keeps its state
there (`state.conf`: the last user and session), and the greeter its own settings and the output
configuration its KWin writes.
