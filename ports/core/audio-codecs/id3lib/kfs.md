## About

id3lib is a C++ library for reading, writing and stripping [ID3]{.idx} v1 and v2 tags in MP3
files, with a C interface, and it installs the `id3tag`, `id3info`, `id3convert` and `id3cp`
commands. The patches beside it are Alpine's set for this release: standard C++ headers, the
`iomanip.h` check, a `bool` typedef that C23 rejects, the UTF-16 writer, a null-pointer check,
a stack overrun and an insecure temporary file. In KDOS, `kwave` links it.

## Patches

- `10-fix-compilation-with-cpp-headers.patch` — Includes `<cstring>` in `id3lib_strings.h` and `writers.h`, which call `memcpy` without including the header that declares it.
- `30-fix-utf16.patch` — Reads the bytes of a UTF-16 string through an `unsigned char` pointer when writing it, so a byte with its top bit set is not sign-extended into the code unit it belongs to.
- `50-remove-outdated-check.patch` — Drops `iomanip.h`, the pre-standard C++ header, from the list of headers `configure.in` refuses to build without; nothing in the library includes it.
- `60-id3lib-missing-nullpointer-check.patch` — Checks that the tag header has its version information (`_info`) before reading its extended-header flag in `header_tag.cpp`.
- `61-fix_vbr_stack_smash.patch` — Raises the largest Xing VBR header `mp3_parse.cpp` will read from 116 to 120 bytes, the size of a header with every optional field; with 116, reading such a header overruns the stack buffer it is copied into.
- `CVE-2007-4460.patch` — Writes a rewritten tag through the temporary file `mkstemp` created whenever `mkstemp` exists, instead of a predictable name opened with `fstream` under GCC 3 and later (CVE-2007-4460).
- `bool-typedef.patch` — Skips the C `typedef int bool` in `globals.h` under C23, where `bool`, `true` and `false` are keywords and the typedef is an error.

## Notes

- **The autotools are run by hand, in this order.** The shipped `configure` and libtool are
  generated by Autoconf 2.53a and libtool 1.4.2, and `50-remove-outdated-check.patch`
  edits `configure.in`, so the build system is regenerated; `aclocal -I m4` is what finds id3lib's
  own macros in `m4/`, among them the iconv probes. `autoheader` is left out on purpose: the
  shipped `config.h.in` is the one the sources expect, and `autoheader` would rewrite it from the
  obsolete `acconfig.h`.
- **zlib comes from the system.** With `libz` found, the copy bundled under `zlib/` is configured
  but not built, and nothing from it is installed.
- **The last line of `build.sh` is a check, not an install step.** id3lib compiles its iconv text
  conversion only when `configure` finds `<iconv.h>` and its `ID3_UNICODE` macro finds, by running
  a test program for each, an iconv name for UTF-8, UTF-16, UTF-16BE and ASCII; when any is
  missing it falls back without a warning to its own converter. `nm -D` on the installed
  `libid3-3.8.so.3` must show `iconv_open` as an undefined symbol, so the fallback fails the build
  instead of shipping.
