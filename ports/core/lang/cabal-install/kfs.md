## About
`cabal`, the command that solves, builds and installs Haskell packages. In KDOS it is the build
tool of the Haskell ports that come after it, [pandoc](#port-pandoc) and
[shellcheck](#port-shellcheck), which their recipes run as `cabal v2-install` against a local
repository made from their vendor bundles (see
[The Haskell bundle](https://github.com/kunaldawn/kdos/blob/main/docs/kdos/05-developer/writing-ports.md#the-haskell-bundle)).

cabal-install is itself a Haskell program with Hackage dependencies, and there is no `cabal` to
build it with before it exists. The recipe uses upstream's `bootstrap/bootstrap.py`, which builds
each dependency and then cabal-install with each package's `Setup.hs` and the installed
[ghc](#port-ghc) alone. The dependencies are the port's vendor bundle, the second `sha256 =` line,
laid out in `_build/tarballs` where the script looks for a prefetched set: `<pkg>-<ver>.tar.gz`
and the revised `<pkg>.cabal` beside it. Before it builds each package the script checks both
files against the plan's hashes; its build step never downloads, so a missing or altered file
stops the build.

## Flags
- `-w` — The GHC `bootstrap.py` compiles with: the system's `/usr/bin/ghc`.
- `-d` — The bootstrap plan, `bootstrap/linux-<ghc>.json` from the cabal source, chosen by the
  recipe's `hsplan` helper. It lists every package to build, in order, with its version, its
  revision and its hashes, solved against one exact GHC release.
- `--no-archive` — Leaves the built `cabal` in `_build/bin` instead of packing it into a
  distribution archive; the recipe installs it from there.

## Notes
The plan is solved against one exact GHC: `bootstrap.py` takes each package the plan marks as
coming with GHC from the installed compiler's package database, at exactly the version the plan
names, and stops when GHC has another. The recipe's `_ghc` helper, which picks the plan, therefore moves
with the [ghc](#port-ghc) port: a GHC bump with no matching `bootstrap/linux-<version>.json` in
the cabal source cannot build this port, and the vendor bundle is generated again from the new
plan.

The manual page is not in the source; it is generated by the built program itself, with
`cabal man --raw`, during the install. The bash completion file comes from the source tree.
