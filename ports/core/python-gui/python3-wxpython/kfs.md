## About
[wxPython]{.idx} is the Python binding of [wxWidgets](#port-wxwidgets), the `wx` package, built
here against the tree's GTK 3 wxWidgets rather than a copy of its own. Python programs written in
wx import it; in the tree, CHIRP and KiCad depend on it. The binding's C++ sources, generated by SIP, ship
in the release archive under `sip/cpp`, so the build compiles them and runs no SIP. The SVG module
`wx.svg._nanosvg` ships only as Cython source, which [python3-cython](#port-python3-cython)
translates during the build.

## Flags
- `--use_syswx` — build against the wxWidgets already installed, found through its `wx-config`,
  and skip building and installing the copy in wxPython's source tree. It implies `--no_magic`, so
  no wxWidgets libraries are bundled into the package.
- `--gtk3` — the GTK 3 port of wxWidgets, the one [wxwidgets](#port-wxwidgets) is built as.
  Upstream's default, named.
- `--release` — mark the build as a release: the generated `wx/__version__.py` records the build
  type as `release` rather than `development`, which `wx.PlatformInfo` reports.
- `--jobs="$KDOS_JOBS"` — compile with the tree's job count.
- `--destdir="$PKG"` — with `--extra_setup="--prefix=/usr"`: install into the staging directory,
  which `build.py` hands to `setup.py install` as `--root`, under the `/usr` prefix.
- `-Wl,--strip-debug` — appended to `LDFLAGS`: drop debug information at the link. wxPython's waf
  build adds `-g` to every compile of the extension modules, so without it
  each `.so` would carry its debug sections; `build.sh` checks that `_core` has no `.debug_info`.

## Patches
- `no-stacktrace.patch` — in the generated binding for `wxAppTraits`, makes `GetAssertStackTrace()` return an empty string instead of calling the wxWidgets method. wxWidgets declares that method only with `wxUSE_STACKWALKER`, which its configure turns off when `backtrace()` and `<execinfo.h>` are missing, as they are on musl; the generated code would otherwise call a method the installed headers do not declare.

## Notes
After the install, `build.sh` checks that the core extension `wx/_core.*.so` and the SVG module
`wx/svg/_nanosvg.*.so` are in the package, so a build that skipped either fails rather than
shipping a `wx` package that cannot be imported.
