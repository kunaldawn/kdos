## About
[PyQt6]{.idx} is Riverbank's set of Python bindings for Qt 6: one extension module per Qt module,
`PyQt6.QtCore`, `PyQt6.QtWidgets` and the rest, generated by [SIP](#port-python3-sip) and built
by [PyQt-builder](#port-python3-pyqt-builder). Calibre, Picard, Spyder and the other Python
applications written in Qt 6 import it. The bindings for Qt WebEngine are the separate
[python3-pyqt6-webengine](#port-python3-pyqt6-webengine) port.

The package also carries the `pyuic6` and `pylupdate6` tools, the Qt Designer plugin that lets
Designer load widgets written in Python, and the `dbus.mainloop.pyqt6` module, which runs
[dbus-python](#port-python3-dbus) on Qt's event loop.

## Flags
- `--confirm-license` — accept the GPL terms without the interactive prompt, which would
  otherwise wait on standard input for `yes`.
- `--qmake /usr/lib/qt6/bin/qmake` — the qmake whose Qt the bindings are built against. Qt 6
  keeps its tools under `/usr/lib/qt6/bin` and puts its `qmake` on `$PATH` only as `qmake6` (see
  [qt6-qtbase](#port-qt6-qtbase)); the plain `qmake` sip-build would otherwise find is Qt 5's.
- `--qmake-setting "QMAKE_CFLAGS_RELEASE = $CFLAGS"` — with the matching `QMAKE_CXXFLAGS_RELEASE`
  and `QMAKE_LFLAGS_RELEASE`: replace the release flags of qmake's own mkspec with the tree's, so
  the extension modules are compiled and linked like every other port.
- `--qmake-setting "QMAKE_RPATHDIR ="` — empty the list of run-time search paths qmake links into
  each module, so none carries an `RPATH` entry (see
  [What the package lint refuses](../../../../docs/kdos/05-developer/writing-ports.md#what-the-package-lint-refuses)).
- `--api-dir /usr/share/qt6/qsci/api/python` — also generate `PyQt6.api`, the QScintilla API
  file a QScintilla editor reads for Python autocompletion, into the directory where
  [qscintilla](#port-qscintilla) looks for it. Without the switch no file is generated.
- `--disable QtPdf` — with `--disable QtPdfWidgets`: leave out the bindings for Qt PDF. Qt PDF is
  built by [qt6-qtwebengine](#port-qt6-qtwebengine), in the same phase but not in `depends`;
  sip-build builds the bindings of every Qt module it finds, so without these switches whether
  they were in the package would depend on build order.
- `--no-make` — only generate the build directory; `build.sh` runs `make` there itself.

## Notes
sip-build runs a small configuration test for each Qt module and leaves out, without an error,
the bindings of any module whose test fails. After the install, `build.sh` checks that each module
the package is meant to carry, from `QtCore` to `QtNfc`, has its extension in
`site-packages/PyQt6`, and that the dbus main-loop module is there; a Qt module missing from the
build root stops the build instead of shipping a smaller PyQt6. Every Qt module checked is in
`depends` for that reason.
