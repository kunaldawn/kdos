## About
[PyQt5]{.idx} is Riverbank's set of Python bindings for Qt 5: one extension module per Qt 5
module, `PyQt5.QtCore`, `PyQt5.QtWidgets` and the rest, generated by
[SIP](#port-python3-sip) and built by [PyQt-builder](#port-python3-pyqt-builder). In the tree,
GNU Radio, gr-osmosdr and pyqtgraph depend on it. The package also
carries `pyuic5` and `pylupdate5`, the Qt Designer plugin for widgets written in Python, and the
`dbus.mainloop.pyqt5` module, which runs [dbus-python](#port-python3-dbus) on Qt's event loop.

## Flags
- `--confirm-license` — accept the GPL terms without the interactive prompt, which would
  otherwise wait on standard input for `yes`.
- `--qmake /usr/lib/qt5/bin/qmake` — the qmake whose Qt the bindings are built against: Qt 5's,
  under its own prefix (see [qt5-qtbase](#port-qt5-qtbase)).
- `--api-dir /usr/share/qt5/qsci/api/python` — also generate `PyQt5.api`, the QScintilla API file a
  QScintilla editor reads for Python autocompletion, into `qsci/api/python` under Qt 5's data
  directory, where a Qt 5 build of QScintilla looks for it; the tree's
  [qscintilla](#port-qscintilla) is built for Qt 6. Without the switch no file is generated.
- `--disable QtBluetooth` — and the same switch for `QtNfc`, `QtLocation`, `QtPositioning`,
  `QtSensors`, `QtWebChannel`, `QtRemoteObjects`, `QtTextToSpeech`, `QtXmlPatterns`,
  `QtQuick3D`, `QtWebKit` and `QtWebKitWidgets`: no bindings for Qt 5 modules the tree does not
  port, so sip-build does not test for them.
- `--no-make` — only generate the build directory; `build.sh` runs `make` there itself.

## Patches
- `sip-minimum-abi.patch` — adds `%MinimumABIVersion "12.15"` to `sip/QtCore/QtCoremod.sip`, which every other module imports. The sip in the tree refuses to generate a module that targets a sip ABI major version without a `%MinimumABIVersion` naming it, and [python3-pyqt5-sip](#port-python3-pyqt5-sip) provides that ABI.

## Notes
No `--qmake-setting` for the compiler flags is needed here, unlike
[python3-pyqt6](#port-python3-pyqt6): Qt 5's mkspecs read `CFLAGS`, `CXXFLAGS` and `LDFLAGS`
from the environment through a patch of `qt5-qtbase`'s, and Qt 5 is built with no `RPATH`.

sip-build leaves out, without an error, the bindings of any Qt module whose configuration test
fails. After the install, `build.sh` checks that each module the package is meant to carry, from
`QtCore` to `QtXml`, has its extension in `site-packages/PyQt5`, and that the dbus main-loop module
is there; every Qt 5 module checked is in `depends` for that reason.
