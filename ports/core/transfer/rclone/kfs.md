## About

rclone copies and synchronises files between local directories and remote storage. The phase list
names it for `rclone check`, which compares two directory trees by content and reports every file
that differs or is missing, so it answers whether a copy to a second disk is complete.
`rclone mount` serves a tree through FUSE, running fuse's setuid `fusermount3`, so
[fuse](#port-fuse) is in `depends`.

## Flags

- `-tags noselfupdate` — Build without the `selfupdate` command, which downloads a release binary
  and writes it over the running one; here that file is `/usr/bin/rclone`, which belongs to the
  package.
- `-X github.com/rclone/rclone/fs.Version=v$version` — Set the version string `rclone version`
  prints. Without it rclone reports the tag compiled into the source with a `-DEV` suffix,
  `v<version>-DEV`.
- `CGO_ENABLED=0` — Build without cgo, the tree's usual setting for a Go port; the mount is
  rclone's pure-Go FUSE client.

## Patches

- `no-embedded-gui.patch` — Removes the `cmd/gui` import from `cmd/all/all.go`, so `rclone gui` is not compiled in. That command embeds `cmd/gui/dist.zip`, a prebuilt web bundle this tree does not build, and has no build tag to leave it out. `rclone rcd --rc-web-gui` is unaffected: it fetches its interface at run time and embeds nothing.

## Notes

The modules come from the vendor bundle, `rclone-vendor-<version>.tar.xz`, made by `ports/fetch`
with `go mod vendor`; `build.sh` unpacks it before applying the patch and builds with
`-mod=vendor` (see
[Vendoring](../../../../docs/kdos/05-developer/writing-ports.md#vendoring)). The completions are
generated by the binary just built, so they list the commands it has.
