## About

GNU m4 is the macro processor. Few people run it by hand, but autoconf is written in it: every
`configure` script is generated by running m4 over `configure.ac`, so [autoconf](#port-autoconf)
depends on it, and so does any port whose `build.sh` runs `autoreconf`. [bison](#port-bison) and
[flex](#port-flex) run it each time they generate a parser or a scanner. `20_selfhost` builds it
because the GMP and GCC builds of that phase run it (see
[The toolchain rebuilt as packages](../../../../docs/kdos/05-developer/how-kdos-is-built.md#the-toolchain-rebuilt-as-packages-20_selfhost)),
and `30_foundation` names it again among the build tools it installs first.

The bootstrap of Part III builds no m4, so this port is the first m4 in the root.

## Flags

- `-std=gnu17` — appended to the exported `CFLAGS`, so it follows the tree's `-std=gnu11` and
  wins: m4 is compiled as GNU C17.
- `-D_GL_ATTRIBUTE_NODISCARD` — define gnulib's macro of that name as empty, so gnulib's headers,
  which define it only when it is undefined, leave it so. gnulib otherwise expands it to `[[__nodiscard__]]` or
  `__attribute__ ((__warn_unused_result__))` on functions whose result must not be ignored, which
  only changes what the compiler warns about.

## Notes

Built with the tree's compiler and C library, m4 configures and compiles without a warning, and
links to a byte-identical `m4`, with both settings above left out: neither changes the build as it
stands.
