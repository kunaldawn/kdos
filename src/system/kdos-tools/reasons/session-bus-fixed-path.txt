title: one session bus at $XDG_RUNTIME_DIR/bus, never dbus-run-session
path: /etc/kdos/user-services/10_dbus.sh
port: dbus

dbus-run-session listens on unix:tmpdir=/tmp — a pathname socket in the HOST's
/tmp, which the appbox does not share. Every alien app then sees a dangling
DBUS_SESSION_BUS_ADDRESS: GApplication single-instance breaks (each impatient
re-click spawns another FULL instance), dconf and the a11y stack stall, and
notifications go nowhere.

/run/user/1000 IS shared with the box, so one fixed address is valid on both
sides. The per-user service starts the bus there before the login goes on, so
Plasma finds the variable set and starts no private bus of its own.

Two traps encoded in that service: the address must carry NO guid — a bus
restarted at the same path with a new guid kills zbus clients with "Server
GUID mismatch" — and you must not add a second <listen> via dbus config
instead, because a multi-address environment hits the same crash.
