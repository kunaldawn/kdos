title: a swapfile is made differently on each filesystem, and fails at NEXT boot
cite: kinstall
port: kdos-installer

btrfs needs the file NOCOW and uncompressed, which is what `btrfs filesystem
mkswapfile` is for; swapon refuses a fallocate'd one with "Invalid argument".
fallocate leaves unwritten extents, and whether swapon takes those on xfs and
f2fs depends on the kernel (the KDOS kernel does), so those two get a file dd
writes out in full. So ext4 gets fallocate, xfs and f2fs get dd, btrfs gets
mkswapfile.

The failure is at the next boot's `swapon -a`, with no swap and nothing saying
why. Same table, same file: fs_passno is 1 for ext4 and 0 for everything else,
because a non-zero pass is an instruction to run a checker and there is no
fsck.btrfs worth running.
