title: without mimeinfo.cache beside them, MimeType lines are never consulted
cite: kdos-appbox genlaunchers
port: kdos-appbox
port: shared-mime-info

No alien app appears in any "Open with" dialog and none can be a default
handler. genlaunchers writes the cache beside the box launchers, because
that directory is not /usr/share/applications and no package install touches
it. kpkg's shared-index trigger writes the host's
/usr/share/applications/mimeinfo.cache.

The other half is the database itself: shared-mime-info builds
-D update-mimedb=false, so the package carries packages/freedesktop.org.xml
and nothing else — no globs, no mime.cache. Without them /usr/share/mime is
one directory and every consumer asking "what type is this file" gets no
answer. kpkg's shared-index trigger writes them: every install or removal
whose manifest touches usr/share/mime/packages/ runs update-mime-database
over the whole tree afterwards (writing-ports.md, "Shared indexes").
