title: the initramfs uses util-linux switch_root, never one that chroot()s
path: /usr/sbin/switch_root
port: util-linux

A switch_root that wipes the initramfs and chroot()s, and never does
mount(newroot, "/", MS_MOVE), leaves the mount-namespace root on the EMPTIED
rootfs with the real root parked at /newroot. Anything that JOINS a mount
namespace via setns(CLONE_NEWNS) — podman exec, distrobox enter, nsenter -m —
gets that empty rootfs as / and every path ENOENTs
("crun: executable file 'echo' not found").

podman run still works, because it CREATES the namespace rather than joining
one, which is what makes this so confusing to diagnose.

Tell-tale: readlink /proc/<pid>/root prints /newroot. `kdos doctor` checks it.
script/phases/70_image/090_initramfs.sh copies util-linux's switch_root and
refuses one whose --version does not name util-linux — keep it that way.
