# Xz

xz compresses and decompresses the `.xz` format, and its library, liblzma, does the same for any
program that links it. Inside the chroot, most builds begin by unpacking a `.tar.xz`, so xz has to
exist in the root before the first port is built. This page shows the commands of
`script/phases/10_bootstrap/050_xz.sh` and explains them.

**Source:** the archive of the [xz](#port-xz) port\
**Installs into:** `build/fs/usr`\
**Approximate build time:** 0.2 SBU

### The meaning of the configure options

`--host=$KDOS_TARGET`
: Compile with the cross toolchain. No `--build` is given, so configure runs its own test of
  whether it is cross-compiling. The test program runs in the container and configure concludes
  that it is not (see [Part III](intro.md#the-shape-of-a-step)); xz's configure tests then run in
  the container. The programs are still compiled and linked by the cross toolchain against
  `build/fs`.

`--prefix=/usr`
: Install under `/usr`.

`--disable-static`
: Build the shared liblzma only. Nothing in the [bootstrap]{.idx} links it statically.

No switch names native-language support, so configure's default holds: it finds the GNU gettext
functions in musl itself and builds xz with translated messages, installing their catalogues under
`/usr/share/locale`.

The `rm` deletes `liblzma.la`, the libtool archive the install writes. No package will own it, and
libtool would copy the build-time paths it records into every library later linked through it (see
[Part III](intro.md#what-the-bootstrap-leaves-behind)).

**Installed library:** [`liblzma.so`]{.idx}.

The [xz](#port-xz) port's page describes each program.

## Built again later

The [xz](#port-xz) port, in `30_foundation`, rebuilds it natively, and kpkg adopts the files this
step installed. It differs in three switches:

- It compiles at `-O3` instead of `-O2`, by substituting the level in `CFLAGS` and `CXXFLAGS`
  before configure runs.
- It passes `--enable-nls`, which states the default the bootstrap build already took, and
  `--enable-sandbox=landlock`,
  which names the Landlock sandbox outright rather than leaving the choice to configure's
  detection.
- It leaves out `--disable-static`, so the package carries `liblzma.a` as well.
