# Sed

GNU sed is the stream editor. Configure scripts and the makefiles they write call it constantly, so
every build `20_selfhost` runs inside `build/fs` depends on it. `068_sed.sh` cross-compiles sed from
the same source tarball as the [sed](#port-sed) port and installs it into `build/fs`.

**Approximate build time:** 0.4 SBU

### The meaning of the configure options

`--host=$KDOS_TARGET`, `--build=$(build-aux/config.guess)`
: A cross build, made by the `x86_64-kdos-linux-musl` compiler for KDOS, with configure told from
  the start that it cannot run what it compiles. [Patch](067-patch.md) explains the pair.

`--prefix=/usr`
: The program goes to `/usr/bin`.

`--disable-nls`
: Build no message catalogues: sed prints its messages in English only.

The root holds no `libacl` or `libattr` yet, so configure builds sed without ACL or
extended-attribute support; `sed -i` writes its output file without copying either from the
original.

The step then removes the source directory and touches `build/mark/bootstrap/sed`, which makes later
runs skip it (see
[Guards in the early phases](../../kdos/05-developer/build-system.md#guards-in-the-early-phases)).

## Built again later

`30_foundation` installs the [sed](#port-sed) port, which adopts `/usr/bin/sed` from this step.
Besides being a native build with the chroot's
[release flags](../../kdos/05-developer/writing-ports.md#the-release-flags), the port:

- depends on `acl` and `attr` and passes `--enable-acl` and `--enable-xattr`, so `sed -i` carries
  both over to the file it writes;
- passes `--without-libsmack` and `--without-selinux`, so the result does not depend on whether
  either library happens to be installed when it is built;
- installs with `--bindir=/bin`, which on KDOS's merged layout is the same directory as `/usr/bin`.
