# GCC

This step builds the compiler that compiles everything in `20_selfhost`. The cross GCC of
[Part II](../02-cross/gcc.md) runs only in the container, and once the build moves inside `build/fs`
the container is out of reach. `100_gcc.sh` uses that cross compiler to build a native GCC for C
and C++: one that runs on KDOS and produces programs for KDOS. It is built from the [gcc](#port-gcc)
port's source tarball, with the GMP, MPFR and MPC sources compiled into it, and installs into
`build/fs` with the C++ standard library, `libgcc` and the compiler's own programs. It is by far the
longest step of the phase.

**Approximate build time:** 11.5 SBU

## Installation of GCC

The step unpacks four port tarballs, gcc's and those of the three mathematical libraries GCC needs
at compile time, and applies one patch from the gcc port's directory:

<!-- kfs:include script/phases/10_bootstrap/100_gcc.sh lines=24-39 pin=25d54faf987b -->

`t-linux64-lib.patch` changes one line of `gcc/config/i386/t-linux64`: the directory GCC uses for
64-bit libraries becomes `../lib` instead of `../lib64`. The runtime libraries (`libstdc++.so`,
`libgcc_s.so` and the rest) therefore install to `/usr/lib`, and the compiler searches there. On
KDOS `/usr/lib64` is only a link to `lib`, which the [`fs/` overlay](000-file-system.md) creates,
so the libraries have one real directory and every program finds them there.

The three `ln -s` lines put GMP, MPFR and MPC inside the GCC source tree under the names GCC's
top-level configure looks for. GCC then builds them as part of itself and links them statically
into its own programs, so the root needs no separate `libgmp`, `libmpfr` or `libmpc`.

GCC is then configured and compiled in a separate `build` directory:

<!-- kfs:include script/phases/10_bootstrap/100_gcc.sh lines=41-65 pin=e009b586fe0f -->

### The meaning of the configure options

`--host=$KDOS_TARGET --target=$KDOS_TARGET`
: The compiler runs on `x86_64-kdos-linux-musl` and produces code for it. The build machine, the
  container, is guessed and differs from both, so GCC is built by the cross compiler but is itself
  a native compiler: a program it compiles runs on the same system it runs on.

`--with-build-sysroot=$SYSROOT`
: While GCC builds its target libraries, look for the C library's headers and libraries in
  `build/fs`. The cross compiler already knows its system root, but GCC's build runs other tools
  that do not, and this tells them. It is a build-time setting only: the installed compiler looks
  in `/`.

`--prefix=/usr`, `--libexecdir=/usr/lib`
: The drivers go to `/usr/bin`, and the internal programs (`cc1`, `cc1plus`, `collect2`,
  `lto-wrapper`) to `/usr/lib/gcc/`. These are the paths the [`gcc`]{.idx} package installs to, so
  `20_selfhost`'s package replaces this step's files under the same names.

`--enable-default-pie`
: Every program the compiler links is a position-independent executable unless told otherwise, so
  the kernel can load it at a random address.

`--enable-default-ssp`
: Every compile has `-fstack-protector-strong` on by default.

`--disable-nls`
: Build no message catalogues: diagnostics are in English only.

`--disable-multilib`
: Build only the 64-bit libraries; KDOS has no 32-bit userland.

`--disable-libatomic`, `--disable-libgomp`, `--disable-libquadmath`, `--disable-libsanitizer`, `--disable-libssp`, `--disable-libvtv`
: Do not build the atomic-operations, OpenMP, quad-precision maths, sanitizer, stack-protector and
  vtable-verification runtimes. The bootstrap compiler needs C and C++ with their core runtimes
  only, the packaged compiler builds these, and the stack-protector support functions are musl's
  own.

`--enable-languages=c,c++`
: The C and C++ front ends only.

### The meaning of the target-library variables

`CFLAGS_FOR_TARGET="${CFLAGS/-std=gnu[0-9][0-9]/}"`
: The flags for the libraries GCC builds for its target, taken from `script/env/host.env` with the
  `-std=gnu99` cut out. The target libraries choose their own C standard, and a global `-std=`
  would override that choice.

`CXXFLAGS_FOR_TARGET="$CXXFLAGS -nostdinc++"`
: The C++ flags for the same libraries, with the compiler's standard C++ include directories
  switched off. The cross compiler that builds `libstdc++` would otherwise find the `libstdc++`
  headers [`030_libstdc++.sh`](030-libstdcxx.md) installed for it, instead of the headers of the
  library being built.

`LDFLAGS_FOR_TARGET=-L$PWD/$KDOS_TARGET/libgcc`
: The target libraries link against the shared `libgcc_s` this build has just made. The cross
  compiler was built with no shared libraries, so without this `libstdc++` would be linked against
  the static `libgcc` alone.

### The meaning of the make variables

`BUILD_INFO=no-info`
: Do not build or install the Texinfo manuals.

`LIBGCC2_DEBUG_CFLAGS=-g0`
: Compile `libgcc` without debugging information instead of with its default `-g`.

### Links and clean-up

<!-- kfs:include script/phases/10_bootstrap/100_gcc.sh lines=67-76 pin=98903cfdc72a -->

`ln -sv gcc $SYSROOT/usr/bin/cc` makes `cc`, the compiler name make's built-in rules and many
makefiles call, run GCC.

The `rm -f` line removes the libtool archives (`.la`) for `libstdc++`, `libstdc++exp`,
`libstdc++fs`, `libsupc++`, `libitm` and the LTO plugin, and the `libstdc++` pretty-printer script
for gdb. Each `.la` names this build directory in a `-L` and the runtime directory as an `RPATH`,
and libtool copies both into every C++ library linked through it. kpkg drops the `.la` files of a
package, but these are installed outside any package, so nothing later removes them. No package
owns the gdb script either.

Last, the step removes all four source trees and touches `build/mark/bootstrap/gcc`.

## Built again later

`20_selfhost` builds the [gcc](#port-gcc) port last on its list, after the separate
[gmp](#port-gmp), [mpfr](#port-mpfr) and [mpc](#port-mpc) ports it depends on, and `30_foundation`
names it again. That build is the compiler every later phase uses. It applies the same
`t-linux64-lib.patch` and shares this step's `--prefix`, `--libexecdir`, `--enable-default-pie`,
`--enable-default-ssp`, `--disable-nls`, `--disable-multilib`, the `-std=` cut from
`CFLAGS_FOR_TARGET` and `LIBGCC2_DEBUG_CFLAGS=-g0`. It differs in these ways:

- **Its triple.** Configured with no `--host` or `--target` inside the chroot, it is native to
  `x86_64-pc-linux-musl`. What this step installed under `x86_64-kdos-linux-musl` (the target-named
  programs in `/usr/bin`, `/usr/lib/gcc/x86_64-kdos-linux-musl`, `/usr/x86_64-kdos-linux-musl` and
  the C++ headers under that name)
  no package replaces, so the package's install hook, `postinstall.sh`, deletes it.
- **Its languages.** `c,c++,fortran,lto`, with the manual pages and info manuals installed by hand.
- **Its runtimes.** None of the six `--disable-lib…` switches is passed, so the packaged compiler
  ships `libatomic`, `libgomp`, `libitm` and the sanitizer runtimes such as `libasan`.
- **Its libraries.** GMP, MPFR and MPC come from their packages instead of the source tree, and
  `--with-system-zlib` uses the packaged zlib. `--without-zstd` and `--without-isl` keep two more
  optional libraries out.
- **Its own hardening.** `--enable-host-pie` and `--enable-host-bind-now` build GCC's own programs
  as PIE with immediate binding; `--enable-linker-build-id` makes every link it drives carry a build
  ID. `--enable-threads=posix` and `--enable-__cxa_atexit` are stated rather than left to defaults,
  and `--disable-bootstrap` builds the compiler once instead of three times.
- **Its flags.** `CXXFLAGS_FOR_TARGET` carries no `-nostdinc++`, `LDFLAGS_FOR_TARGET` is the
  chroot's `$LDFLAGS`, and `-with-pkgversion="KDOS"` puts `KDOS` in `gcc --version`.
- **Its leftovers.** `cc` is an absolute link to `/usr/bin/gcc`, and the gdb script is moved to
  `/usr/share/gdb/auto-load/usr/lib/` rather than deleted.
