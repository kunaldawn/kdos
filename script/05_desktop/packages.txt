# Everything the desktop is, and nothing the userland already provides.
# The Wayland base (wayland, wayland-protocols, seatd, foot, grim, slurp,
# wl-clipboard, xwayland) is phase 4 — it is useful without a compositor.
#
# See docs/KDOS-DESKTOP.md.

# The compositor library. Pinned and vendored; wlroots breaks API every
# release. Xwayland's xwm needs ICCCM and EWMH, which is xcb-util-wm.
xcb-util-wm
wlroots

# The compositor. src/desktop is on PORT_REPO for this phase only.
kdos-comp

# The security-context-v1 sandbox engine: one tagged Wayland socket per box.
# Separate from kdos-appbox because `run` execs distrobox and cannot hold the
# context's close fd, and because kdos-appbox links no libraries.
kdos-boxsock

# The shell: a character-cell panel on layer-shell, drawn by libktui through
# libkwl. Learns what it shows from wlr-foreign-toplevel-management and
# ext-workspace-v1 — standard protocols, so waybar works here too.
kdos-shell

# The lock screen, and the one setuid-root binary KDOS ships: /etc/shadow is
# root-only and kdos-lock must not be. ext-session-lock-v1 means the compositor
# keeps the screen locked even if the client dies.
kdos-lock

# Suspend, poweroff and reboot for a desktop that is not root. A unix socket in
# /run, gated by SO_PEERCRED — no setuid, no polkit prompt, no logind.
kdos-powerd

# The screen-capture portal. A boxed OBS or browser reaches the screen only
# through xdg-desktop-portal, which has no capture code of its own — the wlr
# backend is what turns the compositor's ext-image-copy-capture and
# wlr-screencopy globals into a ScreenCast session. Screenshot comes with it.
# Phase 4 installs the main portal; this is the half that knows about wlroots.
xdg-desktop-portal-wlr
