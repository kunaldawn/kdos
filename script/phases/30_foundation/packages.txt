# FIRST, AND IN THIS ORDER. These are the build tools recipes reach for without
# naming them in `depends`: a configure script calls pkg-config through
# PKG_CHECK_MODULES, a build.sh runs autoreconf, meson or cmake. Listed ahead
# of every shelf section, they are installed before anything else in the phase,
# in the order kpkgdepends gives this run; bash and toybox are the shell and
# the userland every build.sh runs in. musl, gcc, binutils and m4 are
# 20_selfhost's; naming them here rebuilds one whose recipe changed before
# anything uses it. Under `kdosbuild --port-jobs` this run is the phase's
# serial prefix: it builds one port at a time, and nothing after it starts
# until its last port is installed.

gcc
binutils
make
pkgconf
libtool
autoconf
automake
m4
bison
flex
cmake
meson
ninja
python3
perl
bash
toybox

# 20_selfhost's other ports, after toybox. A toybox upgrade removes the names
# its previous manifest held, so a port whose name toybox compiles out carries a
# release bump and reinstalls here to take the name back; listed ahead of
# toybox, it would rebuild first, lose the name to the upgrade, and be current
# again when 40_lang's toybox run reaches it. zlib, ncurses and readline are
# gcc's and python3's dependencies and rebuild ahead of them whatever this list
# says.

# WHAT mbsync AUTHENTICATES THROUGH, with cyrus-sasl-xoauth2 in 41_system: the
# library ships no XOAUTH2 of its own. cyrus-sasl is the mechanism LOADER —
# client side only, with no saslauthd and no password store; the plugin is the
# mechanism a provider that has withdrawn application passwords requires.
# Without both, an account on such a provider can be read in aerc and sent
# through msmtp and cannot be mirrored into a local Maildir at all.
