#   50_desktop: Desktop
# ---------------------------------
#
# Everything the desktop is, and nothing the userland already provides:
# wlroots, the compositor, the panel, the terminal, the lock screen, the root
# daemons, the input method and the portals. src/desktop and src/daemons are on
# PORT_REPO for this phase only. The Wayland base — wayland, wayland-protocols,
# seatd, foot, grim, slurp, wl-clipboard, xwayland — is 41_system and
# 42_graphics: it is useful without a compositor.
#
# See docs/kdos/03-architecture/session.md for the session shape and
# docs/kdos/04-programs/kdos-comp.md for the compositor.
#
# This list names every port the phase installs and nothing it does not;
# testing/phaseclosure.py fails when a dependency pulls a port in from outside
# it, or when a shelf section names a port an earlier phase installs.

# ---------------------------------
# input — Input-device libraries, keyboard data, input methods and on-screen
# keyboards
# ---------------------------------

# The input method. kdos-comp speaks text-input-v3 to applications and
# input-method-v2 to fcitx5 (the fork's src/input/ime.c); this is the
# thing on the other end of that second protocol. Built Wayland-only — no X11
# frontend, no Qt config tool, no cloud pinyin — and the engines are one per
# language: chinese-addons (pinyin, shuangpin, tables) over libime, anthy for
# Japanese, hangul for Korean.
fcitx5

libime
fcitx5-chinese-addons
anthy-unicode
fcitx5-anthy
libhangul
fcitx5-hangul

# ---------------------------------
# wl — Wayland libraries and protocols, wlroots, and Wayland-only desktop
# utilities
# ---------------------------------

# The compositor library. Pinned and vendored; wlroots breaks API every
# release.
wlroots

# ---------------------------------
# xdg — freedesktop desktop integration: portals, MIME, desktop entries,
# AppStream, tray and indicators, notifications, event sounds, script dialogs
# ---------------------------------

# The screen-capture portal. OBS or a browser, native or boxed, reaches the
# screen only through xdg-desktop-portal, which has no capture code of its own
# — the wlr backend is what turns the compositor's ext-image-copy-capture and
# wlr-screencopy globals into a ScreenCast session. Screenshot comes with it.
# 42_graphics installs the main portal; this is the half that knows about
# wlroots.
xdg-desktop-portal-wlr

# ---------------------------------
# src-desktop — KDOS's own desktop programs, from src/desktop
# ---------------------------------

# The compositor.
kdos-comp

# The security-context-v1 sandbox engine: one tagged Wayland socket per box.
# Separate from kdos-appbox because `run` execs distrobox and cannot hold the
# context's close fd, and because kdos-appbox links no libraries.
kdos-boxsock

# The shell: a character-cell panel on layer-shell, drawn by libktui through
# libkwl. Learns what it shows from wlr-foreign-toplevel-management and from
# ext-workspace-v1: standard protocols, so waybar works here too.
kdos-shell

# The terminal, an xdg-toplevel under kdos-comp. libkvt is the state machine —
# kmscon's, forked — and libkimg is what turns sixel, iTerm2's OSC 1337 and
# kitty's APC into pixels.
#
# It ships BESIDE foot and changes nothing: foot is still the default terminal
# in rc.xml, menu.xml, the .desktop files, favorites and tmux.conf. foot is
# battle-tested and this is not, which is the same trade kdos-res made beside
# btop.
kdos-term

# The lock screen, and one of the two setuid-root binaries KDOS ships:
# /etc/shadow is root-only and kdos-lock must not be. ext-session-lock-v1 means
# the compositor keeps the screen locked even if the client dies.
kdos-lock

# The resource monitor. One binary that is a TTY program on tty1 and an
# xdg-toplevel window on the desktop, because both are the same cell grid: nine
# per-device pages, a sortable process table, and an application rollup that
# names a boxed app by the container supervising it — an identity no other
# Linux monitor can build without systemd cgroup delegation, which this distro
# does not have.
#
# It ships BESIDE btop rather than replacing it: btop is mature, and until this
# has run on real hardware a fallback is worth keeping.
#
# kdos-resctl is built by the same recipe and is the SECOND setuid bit this
# distro ships — three verbs, no paths in argv, gated on `wheel` by real uid.
kdos-res

# The FileChooser portal. xdg-desktop-portal-wlr does ScreenCast and
# Screenshot only, and xdg-desktop-portal-gtk, the backend other desktops fall
# back to, draws GTK's own dialog. Without this, an app's Open and Save dialog
# is whatever its own toolkit draws, carrying none of the desktop's palette,
# chrome or file roots.
# Settings comes with it and hands out the accent.
xdg-desktop-portal-kdos

# The screen recorder. It is a program rather than a shell script because
# xdg-desktop-portal keys a session to the connection that created it and closes
# it when that connection goes: three gdbus calls are three connections, and the
# second is told `Invalid session`.
kdos-record

# ---------------------------------
# src-daemons — KDOS's own root daemons, from src/daemons
# ---------------------------------

# Suspend, poweroff and reboot for a desktop that is not root. A unix socket in
# /run, gated by SO_PEERCRED — no setuid, no polkit prompt, no logind.
kdos-powerd

# Per-app Energy Impact. RAPL is root-only (PLATYPUS), so the sampler is a
# daemon; identity comes free from the fact that every alien app is already its
# own container. Relative shares, never watt-hours.
kdos-energyd

# Wedge protection under memory pressure. Blocks on a /proc/pressure/memory PSI
# trigger and SIGKILLs + process_mrelease()s the largest attributable offender —
# preferring boxed apps, never the desktop's own chrome — at most once per ten
# seconds. Same shape as kdos-powerd: root, foreground under ksvc, SO_PEERCRED
# socket for `kdos doctor`.
kdos-oomd

# Removable media for kdos-shell: mounting is root's and the desktop is not
# root. udisks2, in 43_toolkits, serves the toolkit applications (K3b,
# Dolphin's devices, the image writers) beside it; this daemon stays the
# authority for the shell.
#
# Same shape as kdos-powerd: root, foreground under ksvc, an SO_PEERCRED
# socket, and a protocol whose only argument is a row number out of a list the
# daemon published, so a client can never name a device or a mountpoint.
kdos-mountd

# Packs. An application is one signed EROFS image with a KDOS footer on the
# end, and this is the only thing on the machine that mounts one: it verifies
# where it mounts, composes a box's root filesystem out of an overlay of them,
# and takes an id out of the list it published rather than a path. Mounting as
# ROOT is what makes overlay whiteouts real: a box's root is composed from the
# packs as they are, with no flatten step.
kdos-packd
