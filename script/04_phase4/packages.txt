#   Phase 4: User-space + Wayland base
# ---------------------------------

# This phase installs the rest of the user-space:
#   - core build/runtime utilities and ISO tooling
#   - the services every distro has: clock, logs, manual pages
#   - service and auth infrastructure (dbus, polkit, NetworkManager)
#   - power-user CLI tools (the actual workspace)
#   - container layer (podman + distrobox) for fat alien apps
#   - the Wayland base and Xwayland, but NOT the desktop
#   - the graphical stacks (the X11 client libraries, GTK, Qt, KDE Frameworks,
#     WebKitGTK, wxWidgets) and the native applications built on them
#
# The desktop — wlroots, kdos-comp, kdos-shell — is 05_desktop.
# See docs/kdos/05-developer/build-system.md for why the desktop is its own
# phase.

# A toybox upgrade removes the names its previous manifest held, and a toybox
# installed after a port holds that port's names — cmp, readelf, strings,
# gunzip, mount, insmod. So a name toybox compiles out needs a recipe change
# (a release bump) to the port that owns it in the same change: kpkg skips a
# port whose recipe hash is current wherever it is listed, and without the
# bump the name stays missing. These are the owners phase 3 installs before
# toybox, plus sed and findutils, which take back the sed, find and xargs a
# toybox upgrade puts back; ncurses, e2fsprogs and procps-ng are bumped the
# same way and reinstall below. Their place straight after toybox only brings
# the names back before anything later needs them — bzip2's `make` runs `cmp`
# — and a port listed only in phase 3 never reinstalls in a run that continues
# from this phase.
